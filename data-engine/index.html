Инфраструктура сервиса

Справочники, которые Text2me будет обновлять автоматически

Цель Text2me — самостоятельно получать данные из официальных источников, проверять обновления и использовать подтверждённые сведения в формах документов. Пользователь не должен вручную искать индекс, адрес учреждения или актуальные реквизиты.

Текущий этап: созданы коннектор ГАР/ФИАС, SQLite-сборщик, локальный CLI и read-only HTTP API в репозитории. Реальная полная выгрузка не импортирована, API не развёрнут, формы не подключены.
Статус ГАР/ФИАС: ожидает первого запуска

После запуска GitHub Actions здесь появятся дата проверки и результат. Пока нельзя утверждать, что автоматическое обновление уже прошло успешно.

Принцип работы

Один движок — много справочников

Все источники подключаются через единый реестр. Каждый набор данных проходит проверку до публикации новой версии.

01

Получение

Планировщик обращается к официальному источнику и получает открытый файл или разрешённые данные.

02

Проверка

Проверяются источник, формат, целостность архива, обязательные поля и согласованность записей.

03

Безопасное обновление

Повреждённая или неполная выгрузка не заменяет последнюю успешную версию. Ошибка остаётся видимой в журнале.

04

Нормализация

Данные приводятся к общей модели, связываются по устойчивым идентификаторам и готовятся для поиска.

05

Использование

Формы получают нормализованные значения и сведения об источнике и дате последней проверки.

06

Контроль актуальности

Отдельно отслеживаются дата источника, дата загрузки, версия данных и ошибки автоматического обновления.

Ограничение первого этапа

Без платных API

  • Используем бесплатные официальные выгрузки и бесплатные официальные интерфейсы, когда их условия подтверждены.
  • Платные API, в том числе коммерческие нормализаторы адресов, не подключаются.
  • Наличие публичной страницы не считается разрешением на массовый сбор. До автоматизации проверяются условия повторного использования, лицензия и ограничения.
  • Секреты и ключи не хранятся в HTML, JavaScript или публичном репозитории.
  • Для будущего адресного индекса правило такое: если источник недоступен, сохраняется последняя успешно проверенная версия; ошибка не маскируется как успех. Полная выгрузка слишком велика для безопасной автоматической загрузки в стандартном runner. Теперь загрузка начинается только при подтверждённом HEAD-размере в пределах лимита 10 GiB; плановая проверка не скачивает архив. Read-only API-код добавлен, но для запуска нужны реальная база и постоянный сервер.

Очередь разработки

План подключения данных

Очередность учитывает повторное использование общей инфраструктуры и практическую пользу для заполнения документов.

Этап 1 · код реализован

ГАР/ФИАС — адресная основа

Есть коннектор, проверка ZIP, потоковый разбор XML, SQLite-сборщик, CLI и read-only API. Полная выгрузка на реальных данных не собрана: внешние каталоги оценивают размер недавних полных архивов в десятки гигабайт, а текущий HEAD-запрос из runner не завершился вовремя. Нужны сервер с постоянным диском и импорт полной базы; затем можно подключать API к формам.

Этап 2 · частично реализован

Поиск и нормализация адреса

Локальный CLI-поиск и HTTP API реализованы и тестируются на синтетических данных. Реальную базу нужно построить на сервере с большим постоянным диском, развернуть API за HTTPS reverse proxy и подключить формы.

Этап 3

Почтовые индексы

Подключить официальный источник объектов почтовой связи и проверить условия массового использования.

Этап 4

Суды и подсудность

Суды общей юрисдикции, мировые судьи, арбитражные суды, территориальная подсудность и официальные контакты.

Этап 5

Государственные органы и учреждения

Федеральные и региональные органы, МФЦ, медицинские и социальные учреждения, лицензии и официальные контакты.

Этап 6

Организации, классификаторы и право

Реестры организаций, ОКВЭД, ОКТМО, ОКАТО, ОКОГУ, ОКФС, ОКОПФ и официально опубликованные нормативные акты.

Категории справочников

  • Адреса: ГАР/ФИАС, субъекты, муниципалитеты, населённые пункты, улицы, дома и адресные идентификаторы.
  • Почта: индексы и объекты почтовой связи.
  • Суды: суды общей юрисдикции, мировые судьи, арбитражные суды и подсудность.
  • Государственные органы: федеральные, региональные и муниципальные ведомства и подразделения.
  • Здравоохранение и образование: учреждения и лицензии из официальных реестров, если доступ разрешён.
  • Организации: регистрационные сведения и статусы из официальных источников ФНС и других уполномоченных органов.
  • Классификаторы: ОКВЭД, ОКПД2, ОКТМО, ОКАТО, ОКПО, ОКОГУ, ОКФС, ОКОПФ и налоговые коды.
  • Нормативные акты: официальные публикации, версии и даты вступления в силу.
  • Социальные и правовые службы: МФЦ, соцзащита, опека, ЗАГС, прокуратура, приставы, нотариальные и адвокатские палаты, жилищные инспекции и защита прав потребителей.

Кандидаты в источники, тип доступа и состояние проверки перечислены в машиночитаемом реестре. Источник со статусом «требует проверки» не считается подключённым.

Критерии готовности

  1. Источник и условия использования подтверждены.
  2. Автоматическая проверка выполняется по расписанию и может безопасно повторяться.
  3. Последняя успешная версия сохраняется при сбое или повреждении новой выгрузки.
  4. Есть журнал запусков, ошибок, контрольных сумм и версий.
  5. Адресный индекс используется в формах и возвращает источник и дату актуальности.
  6. Тестируются новая версия, отсутствие изменений, недоступный источник, повреждённый архив и восстановление.

Техническая граница: GitHub Pages обслуживает статические файлы. GitHub Actions может проверять и готовить данные по расписанию, но сам по себе не является постоянно работающим API-сервером или базой данных. Код read-only API добавлен, но не развёрнут: для полноценного поиска нужны реальная база, постоянный сервер и подключение API к формам.
