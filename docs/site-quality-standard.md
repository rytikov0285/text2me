# Стандарт качества страниц text2me

Версия: 1.0  
Дата: 2026-10-22

## Цель

Каждая страница должна быть понятна человеку с первого просмотра, доступна для клавиатуры и вспомогательных технологий, а её содержимое должно обнаруживаться поисковыми системами и AI-поиском. Не создавать подписи и страницы ради заполнения интерфейса или поисковых ключевых слов.

## Нормативные ориентиры

- ISO 9241-110:2020 — принципы взаимодействия человека с системой.
- ISO 9241-115:2024 — концептуальное проектирование, интерфейс и навигация.
- ISO 9241-112:2017 — представление информации.
- WCAG 2.2, уровень AA — целевой уровень доступности.
- Google Search Central — индексируемые ссылки, JavaScript SEO, sitemap и структурированные данные.
- Документация OpenAI о ботах — правила доступа OAI-SearchBot и GPTBot.

Это проектные ориентиры, а не заявление о сертификации сайта по ISO или WCAG.

## Правила текста и навигации

1. Одна страница — одна основная задача и один ясный H1.
2. Заголовки H2/H3 описывают содержание следующих разделов и идут без пропуска уровней.
3. Названия ссылок объясняют результат перехода. Не использовать «Подробнее», «Работа», «Для разных задач» без уточняющего контекста.
4. Не показывать посетителю внутренние метки вроде «аудитория», «сценарий», «тип», если они не помогают выбрать действие.
5. Не склеивать название раздела, счётчик, статус и описание в одну строку. Каждый элемент имеет отдельную роль.
6. Счётчики показывать только при наличии корректного источника данных и понятного смысла.
7. Не маркировать функции как работающие, если они демонстрационные, планируемые или требуют неподключённого сервиса.
8. На внутренних страницах должны быть единые основные ссылки и понятное обозначение текущего раздела. Не дублировать меню без отдельной пользовательской цели.
9. Текст должен быть конкретным, коротким и нейтральным. Избегать канцелярита, повторов «для», пустых вводных фраз и маркетинговых обещаний.
10. В начале страницы давать ответ на вопрос «что здесь можно сделать / узнать», затем — действия и подробности.

## Доступность и чтение

- Семантические элементы HTML: header, nav с уникальным aria-label при нескольких навигациях, main, section, footer.
- Предусмотреть ссылку пропуска к основному содержимому.
- Все действия доступны клавиатурой; фокус хорошо заметен и не перекрывается фиксированными панелями.
- У полей есть программно связанные label; ошибки и результаты сообщаются доступным способом.
- Ссылки и кнопки имеют различимые назначения; не использовать кликабельные div вместо интерактивных элементов.
- Проверять контраст, масштабирование, переносы, ширину строки и мобильный экран.
- Не передавать смысл только цветом или иконкой; декоративные иконки скрывать от скринридера.

## Поисковая и AI-доступность

- Каждая публичная полезная страница имеет уникальные title, description и canonical на собственный канонический URL.
- Ссылки на страницы реализованы как обычные HTML-ссылки с корректным href.
- Важное содержимое присутствует в HTML после публикации и не требует обязательного пользовательского клика для обнаружения.
- sitemap.xml содержит актуальные канонические публичные URL без битых и дублирующих адресов.
- robots.txt доступен по ожидаемому адресу опубликованного сайта; проверить его содержимое и ограничения на самом домене.
- Проверять HTTP-ответы, canonical, robots meta, перенаправления и доступность ресурсов.
- Добавлять структурированные данные только там, где они точно соответствуют видимому содержимому; проверять их валидатором.
- Не создавать массово похожие страницы ради ключевых слов. Каждая индексируемая страница должна иметь самостоятельную пользу.
- Для появления в поиске ChatGPT проверить доступ OAI-SearchBot. GPTBot имеет отдельное назначение; разрешение одного не следует автоматически считать разрешением другого.
- Не обещать индексацию или видимость в AI-сервисах: разрешённый обход — необходимое условие, но не гарантия включения в результаты.

## Проверка перед выпуском

Для каждой страницы проверить:

- [ ] H1, title и description описывают реальное содержание.
- [ ] Нет бессмысленных, склеенных, повторных или внутренних служебных подписей.
- [ ] Все ссылки ведут на существующие релевантные страницы.
- [ ] Есть ясная навигация и обозначение текущего раздела.
- [ ] Нет ложных статусов функций и неверных счётчиков.
- [ ] Работают клавиатура, видимый фокус, формы и доступные сообщения.
- [ ] Страница читаема на мобильном экране и при увеличении.
- [ ] URL включён в sitemap, не закрыт случайным noindex или robots.txt.
- [ ] Проверены canonical, HTTP-ответ и содержимое опубликованной версии.
- [ ] Тестируется именно опубликованный сайт, а не только исходный код репозитория.

## Найденные при первичной проверке проблемы

- На главной H1 «Создание документа» слишком узок для сайта, где также есть тексты, знания, инструкции и инструменты. Заголовок заменён на нейтральный «Что нужно сделать?».
- Подпись группы меню «Аудитория и инструменты» объединяла разные основания навигации. Заменена на нейтральную «Разделы и инструменты».
- Поиск главной использует заранее заданный список результатов; часть запросов ведёт на общие разделы вместо конкретных материалов. Это отдельная функциональная задача.
- sitemap.xml содержит не все страницы из дерева репозитория; требуется сравнить опубликованные полезные страницы с картой и добавить отсутствующие канонические URL.
- robots.txt в репозитории указывает sitemap в подпути GitHub Pages и содержит комментарий о размещении в корне домена. Требуется проверить фактически опубликованный robots.txt и его доступность.
- Фраза «Личное · 3 сценарияАудитория: Для разных задач» не найдена в текущем HTML главной и каталога prompts при первичной проверке исходников. Если она видна на опубликованном сайте, проверить источник генерации/кеширование и искать её на всех опубликованных маршрутах, прежде чем считать проблему устранённой.
