# Движок 1. Рекламный и объясняющий текст

**Статус:** спецификация первой продуктовой итерации.  
**Зависимость:** реестр функций и статусов из Движка 0.  
**Результат:** каждая функция text2me описана так, чтобы человек одновременно захотел попробовать её и понимал, что произойдёт.

## 1. Задача

Для каждой функции формировать два различных, согласованных слоя:

- **Рекламный текст:** отвечает «зачем мне это?» и ведёт к действию.
- **Объясняющий текст:** отвечает «как это работает?», «что потребуется от меня?» и «что получится?».

Тексты должны уменьшать неопределённость, а не создавать завышенные ожидания.

## 2. Входной контракт

Одна функция описывается объектом со следующими полями:

| Поле | Обязательное | Содержание |
|---|---|---|
| id | Да | Стабильный машинный идентификатор |
| name | Да | Название функции |
| user_problem | Да | Какую задачу пользователя решает |
| actual_capability | Да | Что действительно работает сейчас |
| inputs | Да | Что пользователь должен предоставить |
| steps | Да | Реальные шаги выполнения |
| output | Да | Какой результат получает пользователь |
| limitations | Да | Ограничения и то, чего функция не делает |
| status | Да | working, demo, in_development, unavailable |
| cta | Да | Одно конкретное следующее действие |
| risk_notes | Нет | Правовые, финансовые, приватностные и другие оговорки |
| audience | Нет | Основная аудитория и ситуация применения |

## 3. Выходной контракт

Для каждой функции создаются:

1. headline — короткое название результата.
2. advertising_copy — конкретная польза без пустых обещаний.
3. cta_label — короткий текст кнопки, начинающийся с понятного действия.
4. how_it_works — объяснение в 2–5 шагов.
5. what_you_need — входные данные и документы.
6. what_you_get — точный результат.
7. limitations — заметные ограничения.
8. privacy_note — куда сохраняются данные и кто может их видеть, если это известно.
9. status_label — соответствует фактическому состоянию.
10. help_text — короткое пояснение рядом с полем или сложным действием.
11. success_message и error_message — понятная обратная связь после действия.

Не нужно выводить все поля в одном месте. Кнопка и заголовок видны сразу; подробная механика располагается рядом или раскрывается по запросу.

## 4. Формулы текста

### Рекламный слой
**Задача пользователя → конкретная выгода → простой следующий шаг.**

Плохо: «Инновационная нейросетевая платформа для решения любых юридических задач».

Лучше: «Подготовьте черновик претензии по вашей ситуации. Ответьте на несколько вопросов, проверьте факты и скачайте документ».

### Объясняющий слой
**Что предоставить → что делает система → что проверить → что можно сделать с результатом.**

Плохо: «Всё автоматически и безопасно».

Лучше: «Укажите продавца, дату покупки и проблему. Система подготовит черновик по введённым данным. Проверьте реквизиты и обстоятельства перед отправкой».

## 5. Обязательные правила

- Не смешивать рекламу и инструкцию в одном длинном абзаце.
- Не называть функцию ИИ, автоматической, облачной или интегрированной, если это не соответствует реализации.
- Не обещать юридическую силу, гарантированный результат, абсолютную безопасность или полную конфиденциальность без оснований.
- Указывать, сохраняются ли данные локально или на сервере; если неизвестно — не придумывать.
- Не создавать фиктивные отзывы, рейтинги, счётчики пользователей и показатели эффективности.
- CTA должен соответствовать действию: «Создать черновик», «Загрузить файл», «Посмотреть пример», а не абстрактное «Начать».
- Для чувствительных действий объяснять последствия до подтверждения.
- На мобильном устройстве сначала показывать короткую ценность, кнопку и необходимое предупреждение; длинную инструкцию можно раскрыть.
- Если функция демо, объяснять границы демо до того, как пользователь вложит значительное время или личные данные.

## 6. Примеры

### Генератор обращения

**Рекламный текст:**  
«Составьте черновик обращения по своей ситуации. Ответьте на несколько вопросов — получите текст, который можно проверить и отредактировать».

**Кнопка:** «Составить обращение»

**Как работает:**  
1. Выберите ситуацию и адресата.
2. Укажите факты и даты.
3. Проверьте сформированный черновик.
4. Скачайте или скопируйте текст.

**Ограничение:**  
«Система помогает подготовить текст, но не отправляет обращение автоматически. Перед отправкой проверьте адресата, сведения и требования принимающей организации».

### Сохранение в личное пространство

**Рекламный текст:**  
«Сохраняйте документы и возвращайтесь к ним позже — без повторного заполнения».

**Кнопка:** «Сохранить в Моё пространство»

**Как работает:**  
«Документ добавляется в ваше рабочее пространство. Перед сохранением проверьте, где хранятся данные: в текущей версии это может быть только этот браузер. Синхронизация между устройствами доступна лишь после подключения серверного хранения и учётной записи».

### Электронная подпись

**Рекламный текст:**  
«Подготовьте документ к электронному подписанию без распечатки — если выбранный тип подписи подходит для вашей задачи».

**Кнопка:** «Разобраться с подписанием»

**Как работает:**  
«Выберите документ и предполагаемый способ подписания, затем прочитайте требования и проверьте доступность нужного сервиса. Не следует показывать шаг “Подписать”, пока настоящая интеграция не подключена».

**Ограничение:**  
«Юридическая сила зависит от вида подписи, документа, сторон и применимого законодательства. Демо-интерфейс сам по себе не подписывает документ».

## 7. Критерии приёмки

Движок готов к подключению, когда:
- у каждой активной функции есть рекламный и объясняющий слои;
- CTA ведёт к реальному следующему действию;
- статус соответствует реализации;
- входы, результат и ограничения изложены простым языком;
- тексты не обещают отсутствующие функции;
- проверены мобильная компоновка и доступность;
- для сохранения, публикации, загрузки и подписи объясняются важные последствия;
- есть набор тестовых описаний функций и проверка обязательных полей.

## 8. Первая реализация

Начать не с генерации свободного рекламного текста на лету, а с **единого реестра описаний функций**. Для сайта использовать проверенные тексты из реестра. Позже можно добавить языковую модель для предложений и вариантов, но публикация текста должна проверяться на соответствие реальным возможностям функции.

Это даёт единый источник правды для главной страницы, каталога, карточек функций, подсказок и будущего личного рабочего сайта.
