# text2me — заключение междисциплинарной комиссии по качеству сервиса

**Дата:** 2026-10-24  
**Сервис:** https://rytikov0285.github.io/text2me/  
**Репозиторий:** https://github.com/rytikov0285/text2me  
**Основа оценки:** исходники сайта, общая оболочка, CSS, навигационные сценарии, статические проверки и ранее выполненный обход опубликованных маршрутов.

## Важное ограничение

Это единое экспертное заключение, составленное по направлениям UX-исследования, UI-дизайна, редакторской работы, доступности, QA, производительности, SEO, продуктовой аналитики и юридического документооборота. Оно **не является заключением внешней команды, не заменяет тестирование с реальными пользователями и не подтверждает соответствие WCAG без инструментальной и ручной проверки**.

## 1. Сводное решение комиссии

Сервис уже имеет значительную информационную структуру и отдельные инструменты, но воспринимается как совмещение нескольких интерфейсных поколений. В коде главной страницы встречаются очень мелкие подписи и элементы навигации; общий CSS содержит много последовательных переопределений, поэтому единообразие нельзя считать гарантированным для всех страниц. Автоматическая проверка URL и якорей полезна, но не доказывает, что кнопка выполняет обещанное действие или что документ корректно формируется.

**Главный продуктовый критерий:** человек должен понять, куда нажать, ввести необходимые сведения, увидеть результат, проверить его, сохранить и скачать документ — без ложного впечатления, что локальное действие уже отправило документ на сервер.

## 2. Рекомендации по направлениям

| Направление | Наблюдение | Рекомендация | Приоритет |
|---|---|---|---|
| UX и пользовательские сценарии | Разные страницы предлагают каталоги, инструменты и сценарии, но единый путь к результату не подтверждён во всех случаях | Для ключевых задач выстроить единый путь: ситуация → уточнения → проверка данных → документ → просмотр → сохранение/экспорт | P0 |
| UI и единообразие | В общей таблице стилей накоплены несколько последовательных тематических переопределений | Ввести общие токены размеров, типографики, отступов, полей, кнопок и карточек; проверять все страницы на единой сетке | P1 |
| Читаемость | В главной странице есть подписи 9–12 px и мелкая навигация; такие размеры затрудняют чтение | Основной текст держать около 16 px; вспомогательный — не мельче 13–14 px; увеличивать line-height и активные области | P1 |
| Информационная архитектура | Параллельно существуют категории документов, тематические ситуации и инструментальные разделы | Показывать контекст страницы, сохранять хлебные крошки и вести от каждой ситуации к релевантным шаблонам | P1 |
| Доступность | Наличие skip-link и некоторых ARIA-атрибутов не доказывает доступность диалогов и динамических элементов | Проверить клавиатурный маршрут, фокус в диалоге поиска, контраст, увеличение до 200%, экранный диктор, семантические подписи | P1 |
| QA и надёжность | Статический обход выявляет ошибки маршрутов, но не клики, состояния и фактические результаты | Добавить Playwright E2E для ключевых сценариев, консольных ошибок, ссылок/кнопок, форм и размеров экрана | P0 |
| Сохранение и приватность | Часть функций хранит данные локально в браузере | Явно указывать локальный характер хранения, добавлять проверку результата сохранения и тесты резервного копирования/восстановления | P0 |
| Производительность | Численные метрики Core Web Vitals не измерялись | Измерить LCP, INP и CLS на опубликованных страницах; сократить блокирующие ресурсы и не добавлять тяжёлые библиотеки без необходимости | P2 |
| SEO | Карта сайта и проверка маршрутов уже есть | Дополнительно проверить канонические URL, метаданные, заголовки H1–H3, индексируемость полезных страниц и отсутствие пустых/дублирующихся страниц | P2 |
| Продуктовая аналитика | Доступность ссылок не говорит о том, что пользователь достигает результата | Измерять обезличенные этапы: выбор ситуации, начало формы, успешная проверка, генерация, сохранение, экспорт и ошибки | P1 |
| Юридическое содержание | Существование конструктора не подтверждает правовую точность итогового документа | Для каждого шаблона иметь перечень обязательных данных, проверяемые правовые основания, дату проверки и ограничения применимости | P0 |

## 3. Первые изменения, применённые в рамках заключения

1. Увеличены мелкие подписи и текстовые элементы главной страницы, включая навигацию инструментов и подписи таблицы файлов.
2. Добавлены заметные контуры клавиатурного фокуса и более удобные минимальные размеры интерактивных элементов.
3. Улучшена типографика боковых панелей, поискового диалога, форм и карточек.
4. Добавлена поддержка системной настройки уменьшения анимации.
5. Улучшена прокрутка к якорям с учётом верхней навигации.

Эти CSS-изменения — первый общий слой, а не доказательство, что каждая страница стала визуально идеальной. Дополнительные правила с повышенной специфичностью применены к главной странице, где старые встроенные стили иначе перекрывали бы новые размеры шрифта. Добавлен Playwright-набор `tests/e2e/site-smoke.spec.js` и workflow `.github/workflows/browser-quality.yml`: они проверяют ключевые маршруты, поведение диалога поиска и горизонтальное переполнение на шести ширинах. Первый завершённый браузерный запуск подтвердил **16/16 тестов успешно**: ключевые маршруты отвечают HTTP 200, диалог поиска открывается и закрывается клавишей Escape с возвратом фокуса, главная страница не имеет документного горизонтального переполнения на ширинах 320, 375, 768, 1024, 1280 и 1440 px. [Результат запуска](https://github.com/rytikov0285/text2me/actions/runs/40115423946). После этого тесты расширены проверкой необработанных ошибок JavaScript на ключевых страницах; результат обновлённого запуска ещё ожидается.

## 4. Обязательные следующие проверки

- [x] Добавлен Playwright-набор для главной, каталога, конструктора претензии, искового заявления, сценария затопления, календаря, рабочего пространства, запроса эксперту, поиска и горизонтального переполнения; дождаться результата первого запуска и исправить найденные сбои.
- [ ] Проверить размеры 320, 375, 768, 1024, 1280 и 1440 px; увеличение браузера до 200%.
- [ ] Проверить клавиатурой открытие/закрытие поиска, логичный порядок фокуса, Escape и возврат фокуса к открывшей кнопке.
- [ ] Проверить генерацию, изменение, локальное сохранение, восстановление и экспорт документа.
- [ ] Убедиться, что пользователь видит достоверный статус действия и не получает ложного подтверждения серверной отправки.
- [ ] Провести ручную проверку контраста и доступности по методологии WCAG-EM; автоматический сканер сам по себе недостаточен.
- [ ] Сравнить реальные показатели скорости и стабильности макета до/после изменений.
- [ ] Проверить юридические шаблоны профильным юристом на актуальность и применимость норм.

## 5. Критерии приёмки

- Нет ошибок загрузки критических JS/CSS и необработанных ошибок JavaScript на ключевых страницах.
- Все ключевые действия имеют ожидаемый результат и видимый статус.
- На мобильной ширине нет непреднамеренной горизонтальной прокрутки страницы и перекрывающих контент фиксированных элементов.
- Основной текст комфортно читается без увеличения; интерактивные элементы доступны с клавиатуры.
- Сохранение и экспорт подтверждаются только после фактического успеха.
- Результат документа можно сверить с исходными данными и обязательными полями сценария.
- Проверки запускаются автоматически при изменениях и не позволяют публиковать критические регрессии.

## Итог

Комиссия рекомендует в первую очередь повысить читаемость, унифицировать компоненты, проверить реальные пользовательские действия и гарантировать правдивость статусов сохранения/экспорта/отправки. Первые общие CSS-улучшения применены. Полный аудит нельзя считать завершённым, пока не пройдены браузерные E2E, ручная доступность, измерение производительности и предметная юридическая проверка.
